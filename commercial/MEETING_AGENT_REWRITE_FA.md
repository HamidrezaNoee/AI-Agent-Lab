# نسخه Agent با منبع بومی ProcessMaker

معماری این نسخه بر اساس دو PMX نهایی `001-5 (1)` و `002-5 (1)` ارسالی در ۲۲ سپتامبر ۲۰۲۶ است. این فایل‌ها از ProcessMaker 3.2.1 Community / PHP 5.6.31 صادر شده‌اند.

| بخش | محل نگهداری و رفتار |
|---|---|
| گردش کار، صورت‌جلسه، گرید، گزارش اقدام، بررسی دبیر و پیوست | خود ProcessMaker و MySQL آن |
| خواندن جلسات توسط Agent | اتصال SELECT به MySQL؛ بدون کپی جدول‌های MTG به SQL Server |
| اطلاعات خود نرم‌افزار Agent | بانک مستقل SQL Server به نام `AVANAgent` |
| دسترسی کاربران، پیش‌نویس دبیر، وضعیت پایش | محتوای رمزگذاری‌شده در `AVANAgent.dbo.AgentState` |
| رخدادهای Agent | `AVANAgent.dbo.AgentAudit`؛ لاگ تریگر ProcessMaker نیست |
| کلید رمزگذاری، رمز اتصال و تنظیمات راه‌اندازی | Volume امن موجود آوان؛ اطلاعات حساس در `.env` قرار نمی‌گیرد |
| ورود سازمانی | Keycloak/OIDC و تطبیق کاربر فعال ProcessMaker؛ GodAdmin با MFA |

SQL Server آوان برای اجرای خود Agent لازم است. قطع آن، گردش کار ProcessMaker را متوقف نمی‌کند. قطع MySQL منبع نیز باعث پاسخ «داده در دسترس نیست» می‌شود؛ داده ساختگی یا آمار بانک قدیمی جایگزین نمی‌شود.

## قابلیت‌های پیاده‌سازی‌شده

- پرسش فارسی با حلقه ابزار Responses API؛ تحلیل اقدامات عقب‌افتاده، واحد/مسئول، وضعیت جلسه، موضوعات تکراری، علائم ریسک و پیشنهاد دستور جلسه.
- محاسبات قطعی آمار در ابزار سرور؛ مدل نمی‌تواند SQL دلخواه اجرا کند. پاسخ دارای تفکیک واقعیت/تحلیل/پیشنهاد و شناسه شواهد است.
- استخراج پیش‌نویس مصوبات و اقدامات از یادداشت، مسئول پیشنهادی از افراد مجاز همان جلسه، اولویت و موعد پیشنهادی، تأیید دبیر و خروجی JSON. خروجی صریحاً «در ProcessMaker ثبت نشده» است.
- تشخیص موعد نزدیک، تأخیر، فقدان موعد/مسئول، گزارش قدیمی، توقف پیشرفت مشاهده‌شده، موضوع تکراری و رشد اقدامات باز واحد.
- جداسازی دسترسی Expert، Manager و SysAdmin، بررسی مجدد دسترسی بعد از پاسخ مدل، محدودیت ماژول‌های لایسنس، CSRF، محدودیت نرخ و بودجه ابزار.

- تاریخچه شخصی رمزگذاری‌شده، ادامه گفتگو و حذف گفتگو با بازبینی مجدد مجوزها.
- ویرایش نسخه‌دار پیش‌نویس، جلوگیری از تأیید نسخه قدیمی، بازگشایی و خروجی ردیف‌های بومی `MTG_Actions` با موعد شمسی.
- BI عمومی همه فرایندها: پرونده‌ها، وضعیت، روند ماه شمسی، تأخیر وظایف، زمان چرخه، گلوگاه مرحله و حجم کار مسئولان؛ پرسش فارسی با ابزار کنترل‌شده و CSV.
- صوت اختیاری: تبدیل فایل/ضبط به متن قابل بازبینی و خواندن پاسخ مستند با صدای مصنوعی. مدیر باید سرویس و مدل صوت را فعال کند؛ صوت انتخابی به سرویس AI فرستاده می‌شود.
- پایش پایدار بدون نیاز به بازماندن مرورگر، نگهداری رمزگذاری‌شده مجوز تمدید OIDC، بازبینی دسترسی در هر نوبت و ثبت وضعیت دیده‌شدن هشدار. مدت تفویض حداکثر ۳۰ روز و محدود به اعتبار IdP است؛ پس از پایان، ورود و فعال‌سازی دوباره لازم است.

ثبت مستقیم در ProcessMaker و ارسال ایمیل/SMS در این نسخه فعال نیستند. خروجی دبیر باید بررسی و توسط کاربر منتقل شود. پایش موجود برای جلسات و اقدامات است؛ BI همه فرایندها هنگام درخواست محاسبه می‌شود.

## نصب یا ارتقای Docker

برای نصب موجود، از checkout فعلی و secretهای همان نصب استفاده کنید. اسکریپت `scripts/update-meeting-agent.ps1` از شاخه `feature/pm-native-agent-store-20260922` یک worktree جدا می‌سازد و فقط سرویس آوان را بازسازی می‌کند. هیچ Volume، بانک یا پرونده‌ای حذف نمی‌شود. پیش‌نیاز آن دریافت همین اسکریپت از شاخه جدید است.

```powershell
$repo = 'D:\A Project\17 meeting ai agent\Azure\AI-Agent-Lab-GitHub'
Set-Location $repo
git fetch origin feature/pm-native-agent-store-20260922
$upgrade = Join-Path $env:TEMP 'update-meeting-agent.ps1'
git show 'origin/feature/pm-native-agent-store-20260922:scripts/update-meeting-agent.ps1' | Set-Content -Encoding UTF8 $upgrade
powershell -ExecutionPolicy Bypass -File $upgrade -SourceRepo $repo
```

برای نصب جدید، شاخه جدید را clone کنید، `scripts/init-security.ps1` را اجرا کنید و سپس:

```powershell
docker compose -f compose.yaml up -d --build
```

نشانی برنامه `http://127.0.0.1:8188` و مدیریت `http://127.0.0.1:8188/admin/` است. رمز اولیه فقط از خروجی بوت نصب گرفته می‌شود و سپس تغییر رمز و TOTP الزامی است.

### ۱. بانک اختصاصی Agent

Compose به‌صورت پیش‌فرض SQL Server 2022 Express داخلی را با Volume دائمی اجرا می‌کند و یک Job یک‌باره بانک `AVANAgent`، دو جدول داخلی و حساب محدود `AVAN_AgentApp` را می‌سازد. رمز مدیر به‌صورت Secret تصادفی نگهداری می‌شود، در UI یا `.env` نمایش داده نمی‌شود و پورت ۱۴۳۳ نیز روی میزبان منتشر نمی‌گردد. هیچ اسکریپت MTG یا EnterpriseProcess2 اجرا نمی‌شود.

در تب «بانک اختصاصی Agent»، اتصال داخلی آماده است. GodAdmin می‌تواند چند اتصال خارجی را با حساب محدود ثبت و ویرایش کند، پیش از استفاده تست بگیرد، یکی را فعال کند یا اتصال فعال را قطع کند. اتصال داخلی قابل حذف نیست و تعویض اتصال اطلاعات بانک قبلی را خودکار منتقل نمی‌کند. برای ساخت بانک روی SQL Server خارجی، حساب مدیر فقط در همان درخواست استفاده و سپس کنار گذاشته می‌شود. فایل DDL مرجع `commercial/sql/AVANAgent_01_schema.sql` است.

### ۲. منبع ProcessMaker

در تب «داده‌های ProcessMaker»، host و port واقعی MySQL، بانک workspace مانند `wf_workflow` یا `bitnami_pm` و یک کاربر اختصاصی دارای حداقل مجوز SELECT را وارد کنید. پورت‌های وب ۸۱، ۸۴ یا ۴۴۳ مربوط به Apache هستند؛ پورت MySQL معمولاً ۳۳۰۶ است و باید تأیید شود.

دسترسی لازم فقط SELECT روی `APPLICATION`، `APP_DELEGATION`، `TASK`، `USERS`، `DEPARTMENT` و `PROCESS` است. نام و واحد از USERS/DEPARTMENT خوانده می‌شود؛ اگر واحد در منبع ثبت نشده باشد، مقدار مصوب مدیر آوان به‌عنوان جایگزین استفاده می‌شود. رمزها یا hash رمز کاربران ProcessMaker خوانده نمی‌شوند.

TLS در حالت فعال، اعتبار گواهی و نام میزبان را بررسی می‌کند. برای CA داخلی، PEM آن در پنل وارد می‌شود. در شبکه داخلی فاقد TLS، انتخاب `no` باید مطابق تنظیم واقعی سرور باشد. منطقه زمانی ثبت تاریخ در PHP/ProcessMaker را نیز دقیق تنظیم کنید؛ پیش‌فرض `Asia/Tehran` است.

شناسه فرایندها حفظ شده است:

- جلسه: `f7f263ea31d8731d212820f220c65a48`
- اقدام: `cd66870095907431106b6dd110e06fa7`

این نسخه مسیر MySQL را برای خواندن داده عملیاتی پیاده‌سازی می‌کند. REST ProcessMaker برای تنظیمات و توسعه بعدی موجود است، اما جایگزینی خودکار REST هنگام قطع MySQL ندارد.

### ۳. کاربران، لایسنس و مدل

اطلاعات سازمان و ورود سازمانی را تنظیم کنید. ابتدا لایسنس معتبر را طبق [راهنمای صادرکننده](licensing/ISSUER_GUIDE_FA.md) فعال کنید. کاربر باید یک بار با هویت سازمانی معتبر وارد شود؛ سپس GodAdmin او را به کاربر فعال ProcessMaker با ایمیل تأییدشده یکسان متصل می‌کند و نقش/مدیر مستقیم را تعیین می‌کند. لایسنس معتبر همان سازمان و شناسه نصب را فعال کنید. در تب «هوش مصنوعی»، کلید API و مدل را ثبت و اتصال را آزمایش کنید.

نگاشت‌های نسخه قدیمی که فقط در AVAN.UserAccess بانک EnterpriseProcess2 بوده‌اند خودکار منتقل نمی‌شوند. این نسخه از بانک قدیمی برای ورود یا گزارش خواندن ندارد؛ نگاشت‌ها باید در بانک مستقل ثبت شوند. کلید رمزگذاری Volume فعلی را نگه دارید؛ برای بازیابی پیش‌نویس‌ها همراه بانک AVANAgent لازم است.

## قرارداد داده و محدودیت‌های روشن

- `APP_NUMBER` شناسه داخلی جلسه در Agent است؛ `MTG_MeetingNo` شماره نمایشی حفظ می‌شود.
- `APP_DATA` با parser داده PHP خوانده می‌شود؛ هیچ PHP، شیء سریال‌شده یا دستور مدل اجرا نمی‌شود.
- ارتباط اقدام فقط پس از تطبیق دقیق `MTGA_ParentCaseUID` و `MTGA_ActionNo` پذیرفته می‌شود. نقشه پرونده والد برای بازیابی با UID استفاده می‌شود؛ برای پرونده‌های قدیمی فاقد نقشه، جست‌وجوی محدود روی داده بومی وجود دارد.
- پایان اقدام از بررسی دبیرِ مربوط به آخرین `submissionVersion` به دست می‌آید. پیشرفت ۱۰۰٪ به‌تنهایی پایان اقدام نیست. در تاریخچه قدیمی بدون نسخه، زمان برابر نشانه کافی برای جدیدبودن بررسی نیست.
- اقدامات بدون پرونده فرزند، فقط پس از تأیید صورت‌جلسه وارد آمار مصوبات می‌شوند.
- سقف snapshot برابر ۲۰۰۰ جلسه و ۲۰هزار اقدام است. پوشش ناقص اعلام می‌شود؛ صفحه جزئیات جلسه با APP_NUMBER بازیابی هدفمند و کنترل مجوز جداگانه دارد؛ تحلیل جمعی همچنان سقف snapshot را رعایت می‌کند.
- گزارش‌های تاریخی فقط به اندازه داده واقعاً موجود در ProcessMaker قابل محاسبه‌اند. رخدادهایی که صرفاً در SQL Server قدیمی ثبت شده‌اند بازسازی یا حدس زده نمی‌شوند.
- تغییر schema یا داده خراب، پاسخ کنترل‌شده می‌دهد؛ آمار ناقص به‌عنوان گزارش کامل ارائه نمی‌شود.

## اعتبارسنجی

آزمون‌های Python شامل دسترسی، داده سریال‌شده، گرید عددی و نام‌دار، تاریخ شمسی، نسخه گزارش/بررسی، پیش‌نویس رمزگذاری‌شده، تأیید تکراری، ابزار مدل و API هستند. مرز SQL Server با test double آزموده شده است؛ اتصال واقعی به SQL Server و MySQL مشتری در این محیط انجام نشده است.

تریگرهای PMX اصلاح‌شده با دستور زبان PHP 5.6 بررسی شدند. سناریوهای اصلی A01/A02 با runtime PHP 7.4 و توابع شبیه‌سازی‌شده ProcessMaker اجرا شدند. این آزمون جای Import و اجرای واقعی در ProcessMaker 3.2.1 را نمی‌گیرد. تست واقعی باید شامل تأیید دعوت، اصلاح صورت‌جلسه، ایجاد اقدامات، ارسال مجدد گزارش، بررسی دبیر، پیوست و اختتام باشد.

## راهنمای قابلیت‌های تکمیلی

[راهنمای کاربری](USER_GUIDE_FA.md)، [بارگذاری ۱۰۰۸ سناریو](scenarios/README_FA.md)، [صدور لایسنس زمانی و کاربری](licensing/ISSUER_GUIDE_FA.md).

BI در هر درخواست حداکثر ۲۰هزار پرونده و ۱۰۰هزار سابقه وظیفه را بررسی می‌کند؛ پوشش ناقص اعلام یا محدودکردن بازه درخواست می‌شود. مبنای دوره، تاریخ ایجاد پرونده است و وضعیت فعلی همان پرونده‌ها گزارش می‌شود؛ این گزارش snapshot تاریخی وضعیت در پایان ماه نیست. عنوان فرایند، وضعیت و تأخیر برای همه فرایندها مشترک است؛ مبلغ، کالا، مشتری یا سایر فیلدهای فرم نیازمند قرارداد داده اختصاصی هستند.

worker پایش برای image فعلی با یک worker وب طراحی شده است. برای HA یا چند replica به lease توزیع‌شده و هماهنگی چرخش refresh token نیاز است. دسترسی BI کاربران عادی بر مبنای ایجاد یا مشارکت واقعی در پرونده، به‌علاوه زیردستان مصوب آوان است؛ SysAdmin به همه فرایندها دسترسی دارد. مجوزهای سفارشی ProcessMaker خارج از این قرارداد خودکار تفسیر نمی‌شوند.
