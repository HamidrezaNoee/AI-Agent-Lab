# آوان | نصب و تنظیمات از داخل برنامه

## نتیجه قابل استفاده در این نسخه

آوان با Docker و **بدون ساخت یا ویرایش فایل .env.production** اجرا می‌شود. اطلاعات اتصال SQL Server، تنظیمات Keycloak/OIDC، نشانی ProcessMaker، شناسه نصب و توکن لایسنس در فضای مدیریتی مستقل از بانک اصلی ذخیره می‌شوند. در اولین بوت، فقط یک رمز تصادفی GodAdmin ایجاد می‌شود. هیچ نام‌کاربری/رمز پیش‌فرض ثابتی در سورس‌کد یا Docker image وجود ندارد.

این نسخه هسته گزارش‌گیری فقط‌خواندنی از `EnterpriseProcess2.MTG` است. نصب مستقل و ذخیره تنظیمات در پنل GodAdmin پیاده‌سازی شده است؛ **صدور اکانت Keycloak، همگام‌سازی و ابطال خودکار کاربران ProcessMaker، کامل‌شدن GodAdmin/SysAdmin، ثبت اقدام در گردش کار و انتشار عمومی هنوز از این کد به‌تنهایی حاصل نمی‌شود.** دسترسی به جلسات تا زمانی که هویت واقعی کاربر، ارتباط PM و لایسنس امضاشده در بانک/سیستم تأیید نشده باشد بسته می‌ماند؛ برنامه داده ساختگی را جایگزین نمی‌کند.

## ۱. فقط Docker Desktop و رمز اولیه GodAdmin

روی همان لپ‌تاپی که Docker Desktop روشن است:

```powershell
$repo = "D:\A Project\17 meeting ai agent\Azure\AI-Agent-Lab-GitHub"
git -C $repo pull --ff-only origin main
cd $repo

# اجرای نسخه محصول؛ به .env یا Notepad نیاز ندارد.
docker compose up -d --build --wait
docker compose ps

# رمز اولیه را فقط یک بار و فقط از کنسول همان سرور بردار.
docker compose exec -T avan python -m commercial.setup_console --take-bootstrap
```

در خروجی نام‌کاربری `godadmin` و رمز موقت تصادفی چاپ می‌شود. رمز را در Password Manager ذخیره کن؛ پس از خواندن، فایل رمز موقت به‌طور خودکار پاک می‌شود و همان دستور دیگر رمز را نمایش نخواهد داد. **این رمز را در گفتگو، عکس یا Git وارد نکن.**

مرورگر همان رایانه: **http://127.0.0.1:8188/admin/**. وارد شو؛ اولین ورود تغییر رمز اولیه (حداقل ۱۶ کاراکتر) را اجباری می‌کند و سپس باید برنامه Authenticator را با کلید یک‌بارمصرف تنظیم و کد شش‌رقمی را تأیید کنی. بعد از این دو مرحله، صفحه «مدیریت سامانه» قابل استفاده می‌شود.

کانتینر و تمام تنظیمات رمزگذاری‌شده در volume پایدار `avan-control-data` نگه‌داری می‌شوند. برای ارتقا `docker compose up -d --build` کافی است؛ هرگز برای به‌روزرسانی `docker compose down -v` اجرا نکن، چون با حذف volume، نصب، تنظیمات محرمانه، شناسه نصب و حساب GodAdmin از بین می‌روند. برای بازیابی نصب باید volume را **همراه با کلید رمزگذاری داخل آن** پشتیبان‌گیری و بازیابی کنی.

## ۲. نصب بانک اصلی از خود پنل

در GodAdmin به صفحه «نصب بانک اطلاعاتی» برو. نشانی SQL Server مانند `host.docker.internal,1433`، حساب DBA معتبر و رمز آن را **فقط در فرم همان عملیات** وارد کن و دکمه «بررسی اختلاف بانک» را بزن. حساب DBA در فضای تنظیمات آوان ذخیره نمی‌شود.

آوان وجود ستون‌های ضروری `MTG.Meeting`، `MTG.MeetingParticipant`، `MTG.ActionItem` و `MTG.Decision` را در `EnterpriseProcess2` بررسی می‌کند. در صورت اختلاف ساختار، مهاجرت اجرا نمی‌شود. بعد از آنکه DBA **نسخه پشتیبان قابل بازیابی بانک اصلی را مستقلاً تهیه و تأیید کرد**، چک‌باکس تأیید را فعال و نام دقیق `EnterpriseProcess2` را برای اجازه تغییر وارد کن. برنامه فقط اسکریپت‌های افزودنی از پیش‌تأییدشده `AVAN` را اجرا می‌کند؛ هیچ SQL دلخواهی از مرورگر نمی‌پذیرد.

خروجی نصب، جداول مستقل `AVAN.Tenant`، `AVAN.UserAccess`، `AVAN.License` و دو حساب جداگانه با دسترسی محدود `AVAN_Reader` و `AVAN_ConfigWriter` است. رمزهای اختصاصی این دو حساب در برنامه ایجاد و در حجم پایدار **رمزگذاری** می‌شوند؛ رمز DBA پس از درخواست نگه‌داری نمی‌شود. هیچ جدول، سند، کیس یا تریگر عملیاتی `MTG` تغییر داده نمی‌شود. اگر حساب‌های محدود از قبل وجود دارند، تنها رمز صحیح خود آنها را یک‌بار در فرم وارد کن؛ برنامه رمز موجود را بازنشانی یا دسترسی بیش از حد قبلی را پنهان نمی‌کند.

برای بازبینی فنی جداگانه DBA، فایل‌های دقیقی که برنامه به‌صورت ثابت اجرا می‌کند:

- `commercial/sql/PRODUCTION_EnterpriseProcess2_01_AVAN_additive.sql`
- `commercial/sql/PRODUCTION_EnterpriseProcess2_02_reader_grants.sql`
- `commercial/sql/PRODUCTION_EnterpriseProcess2_05_config_writer_grants.sql`

`AVAN_ConfigWriter` فقط اجازه پیکربندی `AVAN.Tenant` و `AVAN.UserAccess` دارد، نه نوشتن در `MTG`. روشن‌بودن `TrustServerCertificate` باید تصمیم آگاهانه DBA/IT باشد؛ روش مطلوب نصب CA سازمانی و اعتبارسنجی کامل TLS است.

## ۳. سایر تنظیمات از داخل GodAdmin

در منوی «اتصال SQL Server» می‌توانی نشانی، حساب خواندنی و رمز را مجدداً بررسی و ذخیره کنی. تغییر سرور یا سیاست TLS پس از نصب Writer، مستلزم نصب کنترل‌شده دوباره است؛ برنامه حساب Writer قدیمی را بی‌صدا به سرور دیگر منتقل نمی‌کند.

در «هویت سازمانی»، URL دقیق Realm HTTPS، Audience، JWKS، Client ID محرمانه و Client Secret را وارد کن. آوان سند Discovery و کلیدهای همان Realm را بررسی می‌کند. **Realm، برنامه محرمانه OIDC، مجوز Redirect URI `http://127.0.0.1:8188/auth/callback` و claim امضاشده `tenant_id` باید قبلاً نزد مسئول سامانه هویت وجود داشته باشند.** فرم آوان به‌تنهایی Keycloak یا کلید مدیریتی IdP ایجاد نمی‌کند.

در «ProcessMaker»، نشانی HTTPS، Workspace و OAuth token فقط‌خواندنی را وارد کن. برنامه با API کاربران ProcessMaker اتصال را بررسی و token را فقط در سمت سرور ذخیره می‌کند؛ نگاشت خودکار کاربران به حساب‌های OIDC یا تغییر کیس‌های عملیاتی را از این مرحله برداشت نکن.

در «لایسنس و شناسه نصب»، Installation ID ثابتِ همین volume نمایش داده می‌شود. کلید **عمومی** ناشر باید با اثر انگشت از پیش‌ثبت‌شده در نسخه رسمی نرم‌افزار تطابق داشته باشد؛ GodAdmin مشتری مجاز به تعویض دلخواه ریشه اعتماد و صدور لایسنس برای خود نیست. ناشر باید پیش از توزیع image با `commercial/Pin-PublisherKey.ps1` کلید عمومی معتبر خود را pin کند. اگر تصویر فعلی هنوز با مقدار `PUBLISHER_MUST_PIN...` ساخته شده باشد، واردکردن کلید یا لایسنس در پنل عمداً رد می‌شود. کلید خصوصی ECDSA فقط نزد ناشر باقی می‌ماند. پس از تأیید کلید، توکن امضاشده، شناسه UUID واقعی سازمان، ظرفیت و ماژول‌ها داخل همان پنل بررسی و فعال می‌شوند.

## ۴. دسترسی کارکنان و وضعیت واقعی محصول

هویت کارکنان باید با `sub` امضاشده IdP، شناسه واقعی و **فعال** `PMUserUID` در ProcessMaker و یک Tenant فعال در `AVAN.UserAccess` تطبیق داده شود. نصب پایگاه داده هیچ حساب کارکنان یا نقش SysAdmin جعلی نمی‌سازد. **فرم مدیریت این نگاشت و اتصال کامل پروویژنینگ Keycloak هنوز تکمیل نشده است**؛ تا کامل‌شدن آن، مسئول IT باید اتصال هویت را از مسیر تأییدشده و کنترل‌شده انجام دهد. وجود حساب GodAdmin نصب به‌تنهایی حق مشاهده محتوای جلسات شرکت را اعطا نمی‌کند.

بعد از تکمیل پیش‌نیازهای واقعی، فضای کارکنان در **http://127.0.0.1:8188/** قابل ورود است؛ SQL از `EnterpriseProcess2` خوانده می‌شود و مجوزها باید در هر درخواست دوباره کنترل شوند. آدرس `/health` فقط زنده‌بودن پردازش را نشان می‌دهد، نه اتصال موفق SQL، هویت یا لایسنس.

پورت GodAdmin فعلاً فقط روی `127.0.0.1:8188` منتشر شده و برای نصب محلی طراحی شده است. قبل از انتشار اینترنتی یا دسترسی شبکه، معماری OIDC/BFF و مدیریت نشست چند کانتینری، TLS، audit، حفاظت از پشتیبان volume و مدیریت هویت باید مستقلاً بررسی و تکمیل شوند.

## ۵. در صورت فراموشی کامل رمز GodAdmin

بازیابی فقط توسط مسئول صاحب Docker Host انجام می‌شود؛ هیچ رمز ثابت یا لینک بازیابی بدون هویت وجود ندارد:

```powershell
docker compose exec -T avan python -m commercial.setup_console --reset-godadmin CONFIRM_LOCAL_HOST_RECOVERY
docker compose restart avan
docker compose exec -T avan python -m commercial.setup_console --take-bootstrap
```

این عملیات رمز قبلی و تنظیم احراز هویت دومرحله‌ای را باطل می‌کند؛ اتصال‌های SQL/IdP و داده‌های مستقل volume را پاک نمی‌کند.
