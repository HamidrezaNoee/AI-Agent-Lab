## ایرادهای مشخص پیوست

- در PMX، نوع کنترل `multipleFile` است اما ویژگی `multiple=false` دارد. اوان باید
  آرایه مستندات را حفظ کند؛ انتخاب فایل جدید نباید ارجاع قبلی را حذف کند.
- ارجاع‌های APP_DATA ممکن است آرایه عددی PHP یا رکورد منفرد با نام‌های مختلف
  کلید باشند؛ هر دو شکل معتبر پشتیبانی می‌شوند.
- زمان انتقال بایت‌ها ۱۲۰ ثانیه است، اتصال ۱۵ ثانیه. پاسخ HTML یا شیء error با
  HTTP 200 موفقیت محسوب نمی‌شود. هیچ retry خودکاری برای نوشتن فایل اضافه نشده است.
- اگر انتقال انجام شود ولی اتصال به متغیر فرم شکست بخورد، پیام «موفقیت جزئی»
  می‌گوید ابتدا پرونده بررسی شود. بارگذاری مجدد کورکورانه ممکن است فایل تکراری بسازد.
- محدودیت حجم و پسوند کنترل پیش از ایجاد رکورد بررسی می‌شود. سقف اوان ۲۵ مگابایت
  است؛ محدودیت کمتر PHP، reverse proxy یا Input Document همچنان می‌تواند مانع شود.
- «خواندن فایل» در گفتگو استخراج متن است؛ «بارگذاری فایل در ProcessMaker» پیوست
  واقعی پرونده است. تصویر اسکن‌شده با این تغییر OCR نمی‌شود.

### اصلاح لازم داخل فرایند پرداخت

در فرم «نهایی»، `multipleFileVar004` به Input Document
`3905639646a3a8111427145041951616` متصل است؛ همان متغیر در «کارشناس مالی» و «پرداخت»
به `1474914556ac0ae903b85f3097903206` اشاره می‌کند. در Designer، اتصال فرم نهایی را
با کنترل اصلی مالی همسان کنید و نمایش سند قبلی را با یک پرونده آزمایشی بررسی کنید.
این اصلاح در نصب زنده انجام نشده است.

چند کنترل نمایشی `multipleFileVar001` و `multipleFileVar005` نیز inp_doc_uid خالی

کند؛ ولی پیش از ساخت آداپتور پیوست پرداخت باید نگاشت آن‌ها یکسان و آزموده شود.

## صوت و بازیابی اطلاعات

دکمه «گفتگوی صوتی» در ویرایشگر دبیر، گوی واکنش‌پذیر به سیگنال واقعی میکروفون و
پخش پاسخ دارد. مکث حدود ۱٫۱ ثانیه نوبت را می‌بندد؛ «نوبت من» پاسخ در حال پخش را
قطع می‌کند. بستن، تغییر صفحه، مخفی‌شدن تب یا سقف ۱۵ دقیقه منابع صوتی را آزاد می‌کند.
گفتگو به‌صورت نوبتی STT → گفتگوی موجود → TTS است؛ اتصال WebRTC Realtime و شنیدن
هم‌زمان هنگام پاسخ پیاده نشده‌اند. مسیرهای فعلی تنظیم مدل و مجوزهای اوان حفظ شده‌اند.
پیام صوتی پیش‌نویس را اصلاح می‌کند؛ ارسال نهایی نیازمند اقدام صریح در رابط است.

جستجوی جلسات روی snapshot مجاز همان درخواست با توکن‌سازی فارسی و رتبه‌بندی BM25
انجام می‌شود؛ ترتیب کلمات لازم نیست یکسان باشد. تمام کلمات پرسش باید حاضر باشند.
عنوان، متن جلسه و توضیح اقدام جستجو می‌شوند. حالت substring برای عبارت دقیق باقی
است. این بهینه‌سازی بازیابی واژگانی است، نه اضافه‌شدن embedding یا معنایابی؛ cache
مشترکی که اطلاعات کاربران را مخلوط کند اضافه نشده است.

## گزارش تشخیصی

در صفحه لاگ پشتیبانی، «دریافت گزارش تشخیصی» خروجی JSON می‌دهد. کاربر عادی فقط
فراداده رویدادهای مجاز خودش را دارد؛ GodAdmin علاوه بر آن لاگ ساختاری runtime را
دریافت می‌کند. متن خطا، گفتگو، فایل، صوت، کلید API و رمز در خروجی جدید قرار نمی‌گیرد.
شناسه درخواست پاسخ API برای ارتباط خطای صفحه با runtime استفاده می‌شود.

روی میزبان Docker، با PowerShell مستقل زیر خروجی ساخته و روی شاخه جاری push می‌شود:

```powershell
& 'D:\A Project\17 meeting ai agent\Azure\AVAN-Git-Live-20260927\scripts\export-avan-diagnostics.ps1' -Repository 'D:\A Project\17 meeting ai agent\Azure\AVAN-Git-Live-20260927' -Push
```

بدون `-Push` فقط فایل ساخته می‌شود. اسکریپت فقط فایل جدید را commit می‌کند؛ push
عادی Git سایر commitهای جلوتر از remote در شاخه جاری را نیز می‌فرستد. رویدادهای
قدیمی با rotation حذف می‌شوند؛ هنگام وقوع ایراد زود خروجی بگیرید. این قابلیت پوشش
تمام خطاهای سیستم‌عامل و سرویس‌های خارجی را تضمین نمی‌کند.

## پذیرش روی نصب واقعی

پس از عبور CI، کد بازبینی‌شده را دریافت و فقط سرویس اوان را بازسازی کنید:

```powershell
Set-Location 'D:\A Project\17 meeting ai agent\Azure\AVAN-Git-Live-20260927'
docker compose -p avan-production -f compose.yaml -f compose.pm-local.yaml up -d --build --no-deps avan
```

بسته جلسه/اقدام را در مدیریت فرایندها با نسخه‌های جدید ارتقا دهید؛ سپس با حساب‌های
واقعی دبیر، رئیس و مجری یک پرونده آزمایشی را در هفت مرحله اجرا کنید. دو فایل را به
صورت‌جلسه و اقدام اضافه کنید و در مرحله بررسی هر دو را دانلود کنید. مسیر برگشت
اقدام، ابلاغ جدید، گفتگوی صوتی فارسی و خروجی لاگ همان Request ID را بررسی کنید.
هیچ secret یا volume موجودی نباید بازسازی یا حذف شود.
