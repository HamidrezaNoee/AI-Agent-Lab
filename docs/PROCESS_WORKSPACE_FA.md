# فضای کاری وابسته به فرایند

مدیریت ← اتصالات BPMS ← اتصال ProcessMaker ← «فرایندها و کارتابل‌ها».
برای گردش جلسه، PMX جلسه و اقدامات را معرفی و بسته را فعال کنید. برای سایر
فرایندهای نصب‌شده، «اتصال کارتابل بومی این فرایند» یک کارتابل فقط‌خواندنی می‌سازد.
فعال یا غیرفعال کردن بسته با کنترل نسخه انجام می‌شود.

در پنل کاربر، زیر هر اتصال، فرایند را انتخاب کنید. منوها از قرارداد همان بسته،
مجوز ماژول و وظایف فعلی کاربر ساخته می‌شوند. بسته جلسه بخش‌های پیش‌نویس، تأیید،
صورتجلسه، اجرا، بررسی و پایش دارد؛ بخش‌های وظیفه‌ای بدون وظیفه پنهان می‌شوند.
فهرست جلسات، دستیار، گزارش و هشدار با مجوز ماژول خودشان ظاهر می‌شوند. یک حساب
فقط گزارش‌گیر به وظایف دبیر و پیش‌نویس‌ها دسترسی نمی‌گیرد.

انتخاب یک فرایند، کارتابل، اعلان و پیش‌نویس‌های همان بسته را نمایش می‌دهد.
گزارش، پرسش و سابقه گفت‌وگو نیز با شناسه فرایند منتخب محدود می‌شوند. BI اتصال
همچنان نمای اتصال است. کارتابل بومی عمومی فقط عنوان وظیفه تخصیص‌یافته را نمایش
می‌دهد؛ اقدام یا تأیید عمومی بر مبنای یک PMX ناشناخته اجرا نمی‌شود.

## افزودن آداپتور بعدی

رجیستری قابل اعتماد در `commercial/process_workspace.py` قرار دارد. هر `Adapter`
شناسه، ماژول‌های مجاز، کلیدهای فرایند، منوها و خواننده کارتابل/پیش‌نویس را تعریف
می‌کند. `Section` مرحله، نمای صفحه و مجوز خودش را تعیین می‌کند. آداپتور بومی
`native_tasks_v1` نمونه‌ای مستقل از فیلدهای جلسه است. آداپتور `meeting_v2` اجرای
قراردادهای PMX شناخته‌شده را به runtime دبیر واگذار می‌کند.

برای اجرای فرایند جدید باید نگاشت فرم‌ها، اعتبارسنجی، اختیار فرد تخصیص‌یافته،
پیش‌شرط مرحله و عملیات REST به‌طور صریح پیاده و آزمایش شود. آداپتور را در رجیستری
ثبت و فایل جدید را در Dockerfile تولید کپی کنید. بسته باید UID فرایندهای واقعی
همان اتصال را داشته باشد؛ هم‌پوشانی UID بین دو بسته ممنوع است. قالب جدید را از
نمای generic یا renderer اختصاصی نمایش دهید. کد داخل PMX در AVAN اجرا نمی‌شود.

تحلیل‌های جلسه از `commercial/process_context.py` برای انتخاب درخواست استفاده
می‌کنند. Header انتخاب فرایند فقط در مسیرهای تحلیلی پذیرفته می‌شود و سرور بسته،
اتصال و مجوز را دوباره بررسی می‌کند. عملیات نوشتن از بسته صریح و تخصیص بومی
وظیفه استفاده می‌کند. تاریخچه گفت‌وگو بین بسته‌ها قابل استفاده مجدد نیست.

## به‌روزرسانی نصب موجود

در پوشه checkout واقعی پروژه، تغییرات محلی را پیش از دریافت نسخه بررسی کنید:

```powershell
Set-Location 'D:\A Project\17 meeting ai agent\Azure\AVAN-Git-Live-20260927'
git status --short
git switch feature/pm-native-agent-store-20260922
git pull --ff-only
docker compose -f compose.yaml up -d --build avan
```

اگر نصب فعلی فایل‌های override مانند `compose.pm-local.yaml` یا تنظیم HTTPS دارد،
همان مجموعه فایل‌های `-f` نصب فعلی را در دستور آخر استفاده کنید. Volumeها و
secretهای فعلی را حفظ کنید؛ برای به‌روزرسانی، راه‌اندازی امنیت از ابتدا لازم نیست.
سپس با حساب رئیس، دبیر و مجری، گردش یک پرونده آزمایشی را روی اتصال واقعی بررسی کنید.
