# بازبینی و بازیابی اوان — ۴ اکتبر ۲۰۲۶

مبنای بازبینی: شاخه `feature/pm-native-agent-store-20260922` در commit `721bc48`،
کد تولید و گزارش PowerShell پیوست مالک. این گزارش به معنی اجرای تغییرات روی لپ‌تاپ نیست.

## علت خطای گزارش‌شده

در انتهای گزارش، Keycloak پاسخ `Bootstrap in progress. Retry in 1 seconds.`
می‌دهد و لاگ ایجاد schema را نشان می‌دهد. پیش از آن دستور `docker compose down -v`
اجرا شده و چهار Volume با نام‌های avan-state، avan-ui، avan-keycloak-db و
avan-agent-sql حذف و سپس دوباره ساخته شده‌اند. داده‌های قبلی این Volumeها با Git
بازیابی نمی‌شوند؛ بازیابی نیازمند backup است. داده‌های ProcessMaker بیرون از این
چهار Volume قرار دارند؛ حذف شدن آن‌ها از این گزارش نتیجه نمی‌شود.

در Compose قبلی، شروع AVAN فقط به service_started هویت وابسته بود؛ بنابراین سالم
بودن `/health` اوان آماده بودن realm را ثابت نمی‌کرد. اکنون سلامت Keycloak با
پاسخ HTTP 200 کشف OIDC همان realm سنجیده می‌شود و AVAN منتظر service_healthy می‌ماند.
گزینه‌های health/metrics هنگام build ثبت و start به‌صورت optimized اجرا می‌شود.
ظاهر ورود، CAPTCHA، OTP و رمزهای نصب در این تغییر دستکاری نشده‌اند.

## اجرا در نصب Live ویندوز

ابتدا Docker Desktop را در حالت Linux containers باز کنید. اگر backup داده‌های
قبل از حذف Volume دارید، برای بازگرداندن کاربران و تنظیمات قبلی از همان backup
استفاده کنید؛ ادامه start به‌تنهایی آن‌ها را برنمی‌گرداند.

```powershell
Set-Location 'D:\A Project\17 meeting ai agent\Azure\AVAN-Git-Live-20260927'
git status --short
git switch feature/pm-native-agent-store-20260922
if ($LASTEXITCODE -ne 0) { throw 'Git switch failed' }
git pull --ff-only origin feature/pm-native-agent-store-20260922
if ($LASTEXITCODE -ne 0) { throw 'Git pull failed' }
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-avan-verified.ps1
```

اسکریپت مخصوص پورت‌ها و issuer نصب محلی فعلی است، نه استقرار HTTPS. به‌طور پیش‌فرض
compose.yaml و compose.pm-local.yaml را مصرف می‌کند. هیچ Volume یا secret را حذف
یا بازتولید نمی‌کند. با شکست Docker یا timeout متوقف می‌شود؛ موفقیت کشف realm و
سلامت برنامه را جداگانه می‌سنجد. برای اجرای مجدد بدون build از `-SkipBuild` استفاده
کنید. build، runtime واقعی Docker و اجرای PowerShell در محیط این بازبینی فراهم نبود.

## معماری نقش‌ها و فرایند

هویت سازمانی در Keycloak، حساب و مجوز ماژول در AVAN، نگاشت کاربر به BPMS در
Binding همان Source و اختیار انجام وظیفه در تخصیص زنده ProcessMaker است. حساب
GodAdmin محلی مدیریت سامانه را دارد و از این بابت اختیار اقدام به جای دیگران ندارد.

| نقش کاری | مرحله‌های اوان | مرجع اختیار |
|---|---|---|
| دبیر | دعوت، صورتجلسه، بررسی اقدام، پایش و اختتام | وظیفه جاری تخصیص‌یافته به UID همان کاربر |
| رئیس | تأیید یا درخواست اصلاح دعوت و صورتجلسه | تخصیص مرحله تأیید در همان پرونده |
| اقدام‌کننده | گزارش پیشرفت یا اعلام تکمیل | تخصیص وظیفه اجرای همان اقدام |

نام‌های SysAdmin/Manager/Expert نقش تجاری جلسه را جایگزین نمی‌کنند. کاربر ممکن است
در یک جلسه رئیس و در جلسه دیگر اقدام‌کننده باشد. منوی نقش وابسته به وظیفه جاری است؛
نبود وظیفه به‌تنهایی نشانه خرابی نیست. ایجاد پرونده با OAuth شخصی و مجوز شروع بومی
ProcessMaker انجام می‌شود. MySQL فقط خواندنی می‌ماند؛ نوشتن از REST با حساب خود فرد است.

## فعال‌سازی فرایند موجود

۱. مدیریت ← اتصالات BPMS ← اتصال مورد نظر ← فرایندها و کارتابل‌ها.

۲. اگر قبلاً «کارتابل بومی» ساخته شده، از «بسته قابل تنظیم» گزینه «ارتقای کارتابل
خواندنی به گردش جلسه» همان فرایند جلسه را انتخاب کنید. این گزینه در بازبینی حاضر
اضافه شد؛ قبلاً کارتابل‌های خواندنی در این فهرست نبودند. برای نصب جدید، بسته جدید.

۳. PMX جلسه و PMX اقدام نصب‌شده روی همان اتصال را معرفی و وضعیت را فعال کنید.
پنج مرحله جلسه باید در PMX جلسه و دو مرحله اقدام در PMX اقدام باشند؛ وظیفه هر مرحله
باید مستقل باشد. UID فرم/وظیفه/تریگرها با سرور بررسی می‌شود. برای ارتقا شناسه بسته
حفظ و revision افزایش می‌یابد؛ PMX مربوط به فرایند دیگری رد می‌شود.

۴. در اتصال کاربران به BPMS، هر سه حساب اوان را به نام کاربری/UID واقعی خودشان در
همین اتصال وصل کنید و مجوز ماژول دبیر را بدهید. مجوز سازمان هم باید این ماژول را داشته باشد.

۵. هر فرد در حساب خودش «مجوز عملیات حساب BPMS» را متصل و فرایند را انتخاب کند.
تخصیص کار در ProcessMaker باید به همان UID باشد. حساب مشترک مدیر جایگزین حساب فرد نیست.

اگر فرایند اقدام هم قبلاً یک بسته خواندنی جداگانه دارد، کنترل تداخل UID مانع ذخیره
می‌شود؛ آن را دور نزنید. ادغام چند بسته قبلی در این تغییر پیاده نشده است.

پایش، پیش‌نویس جلسه پیگیری، متن/صوت و خواندن شواهد TXT/PDF متنی وجود دارد.

در این نسخه وجود ندارد. معماری آداپتور برای فرایندهای دیگر قابل توسعه است.

۷۵ آزمون هدفمند موفق: آمادگی HTTP، قرارداد نقش‌ها، ارتقای کارتابل، جداسازی منبع/
فرایند، گردش دبیر، Binding، ساخت حساب و مسیر ورود. پاسخ‌های سرویس بیرونی در آزمون‌ها
شبیه‌سازی شده‌اند؛ این نتیجه اثبات ورود واقعی، ارسال واقعی PM یا کیفیت پاسخ مدل نیست.
syntax فایل JavaScript مدیریت هم بررسی شد. screenshot مرورگر و PowerShell اجرا نشدند.

آزمون پذیرش روی نصب واقعی: یک جلسه آزمایشی با سه حساب مستقل، برگشت دعوت، تأیید
صورتجلسه، گزارش ۶۰ درصد، اعلام تکمیل، برگشت دبیر و تأیید نهایی؛ حساب نامرتبط باید
از بازکردن/ارسال همان وظیفه منع شود. هنوز هیچ حساب یا فرایند زنده کاربر از این محیط
فعال نشده است؛ تنظیمات نصب و داده‌های حذف‌شده اینجا در دسترس نیستند.
